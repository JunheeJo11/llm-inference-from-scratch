- RTX 5070 Ti, WSL2 Ubuntu, torch 2.11.0+cu130 (CUDA 13.0)
- 모델: 과제1 TransformerLM (내 구현), 무작위 가중치와 무작위 입력 토큰 (데이터 읽기 시간 제외)

  활성값 = 4 x { L x [8BTd + 4BTF + 2BhT^2] + BTd + 2BTV } 바이트 (층당 1.078 GiB, 고정분 1.252 GiB)
- 4P와 16P는 거의 정확히 맞음. 16P에서 남는 약 0.02 GiB는 cuBLAS 작업 공간으로 추정 (확인 안 함)
- bf16 활성값을 층 수로 직선 맞춤 (L2, L4, L8 세 점이 한 직선 위):
  - **층당 0.844 GiB** (손계산 1.078의 78%): 행렬 곱 출력이 bf16(2바이트)으로 저장되기 때문으로 추정
  - **고정분 1.901 GiB** (손계산 1.252의 152%, +0.65 GiB): logits(64 x 256 x 10000) 크기 텐서가 손계산의 2개보다 하나쯤 더 저장됨 (bf16 logits, fp32 사본, 직접 짠 cross_entropy 중간값). BTV 텐서 하나가 fp32로 0.61 GiB
- fp32는 활성값이 손계산보다 1.2 GiB 큼: 실제 구현이 핸드아웃 목록에 없는 중간값(마스크 적용, 나눗셈, 형 변환 등)도 저장
- 11/16 학습 summary의 최대 메모리(ts_L2 4.14, ts_base 5.92, ts_L8 9.49)보다 오늘 값이 0.3 GiB 정도 작음: train.py가 기록한 값의 종류는 확인 필요

## 프로파일 (ts_base, bf16, 3스텝)
- 커널 실행 **스텝당 1,424번**
- GPU 커널 시간 비중 (근사): **원소별 연산 약 71%**, 행렬 곱(GEMM) 약 17%, 줄이기(reduce) 약 6%, 복사 약 3%, 기타 약 3%
  - 처음 출력의 "기타 26.9%"에는 내가 붙인 1_forward 이름표 구간(GPU 쪽 약 44 ms/스텝)이 섞여 있었음. 그 값을 빼고 다시 나눈 비중
  - 이름표를 뺀 커널 시간 합은 약 136 ms/스텝, 스텝 시간 138 ms와 거의 같음: GPU가 노는 시간은 적고, 일은 계속 하는데 그 일이 대부분 memory-bound 원소별 연산
- forward 모듈별 (CUDA 이벤트, 기울기 기록 끔, forward 37.45 ms): **attention 73.8%**, FFN 13.6%, lm_head 5.6%, RMSNorm 4.4%, 나머지 1.9%
- GPU 시간이 긴 연산 (3스텝 합): aten::bmm 70.5 ms (333번), aten::mul 61.6 ms, aten::copy_ 59.9 ms (780번), aten::div 50.8 ms, DivBackward0 69.0 ms, aten::add_ 41.3 ms, masked_fill 27.0 ms, exp 13.2 ms

## 해석
- **MFU 15%의 원인은 attention**: 층 하나의 FLOPs는 FFN(약 68 GFLOP)이 attention(약 43 GFLOP)보다 많은데 시간은 attention이 5.4배. attention이 (64 x 16 x 256 x 256) 점수 행렬을 통째로 만들고 그 위에서 나눗셈, 마스크, 수동 softmax(최댓값, 빼기, exp, 합, 나누기)를 각각 별도 커널로 돌림. 강의 6의 수동 softmax와 같은 문제이고, FlashAttention이 푸는 문제
- **bf16이 1.42배만 빠른 이유**: 행렬 곱은 GPU 시간의 17%뿐이고, autocast의 형 변환 복사(aten::copy_, 스텝당 약 20 ms)가 추가로 듦
- 다음에 확인할 것: attention을 torch의 scaled_dot_product_attention으로 바꿔 같은 조건에서 다시 재기 (12/2 FlashAttention 블록)
